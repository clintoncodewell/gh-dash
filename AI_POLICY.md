# AI Contribution Policy

AI-assisted pull requests are welcome in this fork. No special label or disclosure
is required. AI-assisted and entirely human-authored contributions are held to the
same quality, review, and maintenance standards.

This policy applies to `clintoncodewell/gh-dash` only. The upstream
[`dlvhdr/gh-dash`](https://github.com/dlvhdr/gh-dash) project has its own contribution
policy. Do not submit AI-assisted work from this fork upstream unless upstream's
current policy explicitly permits it.

## What we expect

- Understand and be able to explain every change you submit.
- Create or reuse an issue before non-trivial work so the problem and intended
  behavior are agreed before implementation.
- Keep each pull request focused on one coherent change.
- Explain the problem, user impact, and why the chosen approach fits.
- Include useful evidence: tests, terminal output, screenshots, recordings, or
  another reproducible check appropriate to the change.
- Review generated code and prose before submission. Remove speculative,
  irrelevant, unsafe, or needlessly broad changes.
- Own the result: respond to review, fix regressions, and help maintain the code
  you contribute.

## What we will reject

- Unreviewed code dumps or one-shot pull requests the author cannot explain.
- Fabricated test results, benchmarks, screenshots, or citations.
- Changes that expose secrets, private data, or third-party copyrighted material.
- Broad refactors mixed into an unrelated feature or bug fix.
- Pull requests that shift basic validation work onto maintainers.

AI can accelerate the work; it does not transfer responsibility for the work.
